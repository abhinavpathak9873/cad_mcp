cad_mcp · how it works

How an AI drives FreeCAD,
explained so anyone gets it

An AI model can only read and write text. It cannot click buttons in FreeCAD. cad_mcp is a small program that sits in between: it offers the AI a menu of CAD jobs, and when the AI picks one, it quietly runs FreeCAD in the background to do it and reports the result back in text (or as a picture).

1The four players

Think of a restaurant. You order, a waiter takes the order, the kitchen cooks, and the food comes back on a plate.

🧑
YouThe customer. You say what you want in plain words: "make me an L-bracket that holds 300 N".
🤖
The AI clientClaude Code, Codex, Claude Desktop. The waiter who understands you and decides which dishes to order from the kitchen.
🧾
cad_mcp (the MCP server)The order window. It has a printed menu of 45 CAD jobs and turns each order into instructions for the kitchen.
⚙️
FreeCADThe kitchen. The real CAD engine that builds solids, meshes, runs stress analysis and makes drawings. It never talks to the AI directly.
MCP (Model Context Protocol) is just the agreed format for the order slips between the waiter and the order window. Because the format is standard, any AI client that speaks MCP can use any MCP server. It is the "USB plug" for AI tools.

2The big picture

Everything runs on one computer. The AI client starts cad_mcp as a child program and talks to it through two plain text pipes (the program's input and output). For every job, cad_mcp starts a fresh, invisible copy of FreeCAD (freecadcmd), hands it a job slip, and waits for a result slip.

Orange dot: an order travelling to FreeCAD. Blue dot: the result coming back. cad_mcp and FreeCAD run only on your computer; the AI provider (Anthropic, OpenAI) only sees the menu and the results, as part of the chat.

3First, the AI reads the menu

When you open Claude Code (or Codex), it starts cad_mcp and asks one question: "what can you do?" cad_mcp answers with its menu. Each item has a name, a description written for the AI, and a form to fill in (which inputs it needs, and their types). That is all the AI ever learns about FreeCAD.

How a menu item is written (in server.py)

@mcp.tool()
def add_primitive(doc: str, name: str,
        shape: Literal["box","cylinder",...],
        dimensions: dict[str, float],
        position: list[float] = None):
    """Add a primitive solid. dimensions keys:
    box {length, width, height};
    cylinder {radius, height} ..."""
    return run_worker("add_primitive", doc, ...)

A normal Python function. The @mcp.tool() label puts it on the menu.

What the AI actually receives

{ "name": "add_primitive",
  "description": "Add a primitive solid.
     dimensions keys: box {length,
     width, height}; cylinder ...",
  "inputSchema": {
    "properties": {
      "doc":   {"type": "string"},
      "shape": {"enum": ["box","cylinder",...]},
      "dimensions": {"type": "object"}, ...
    }}}

The MCP library turns the function's name, inputs and docstring into this automatically.

Key idea: the description is the AI's only manual. Good descriptions ("units are mm, +Z is up, box origin is its corner") are the difference between an AI that builds the right part and one that guesses.

4One request, step by step

You type: "Make a 60 × 40 × 5 mm aluminium plate." Here is everything that happens, in order. It takes about a second.

  1. You→AI
    You type the request in plain words.
  2. AI
    The model looks at the menu and decides: the right item is add_primitive, with shape box, length 60, width 40, height 5, material aluminium 6061. It fills in the form.
  3. AI→cad_mcp
    Claude Code writes one line of JSON (a tools/call message) into cad_mcp's input pipe.
  4. cad_mcp
    cad_mcp copies the current model file into .history/ (so you can undo), then writes a job slip (job.json: "do add_primitive on bracket.FCStd with these numbers") and a three-line starter script.
  5. cad_mcp→FreeCAD
    It launches freecadcmd job.py: a copy of FreeCAD with no window. Like double-clicking FreeCAD, but invisible.
  6. FreeCAD→file
    Inside FreeCAD, the worker opens bracket.FCStd, runs Part.makeBox(60, 40, 5), tags it with its material, and saves the file.
  7. FreeCAD→cad_mcp
    It writes a result slip (result.json: "ok, volume 12 000 mm³, bounding box …") and exits. FreeCAD is now closed again.
  8. cad_mcp→AI
    cad_mcp reads the slip and sends it back up the output pipe as the answer to the AI's message.
  9. AI→You
    The model reads the numbers, maybe calls more tools (add holes, render, check mass), then tells you what it did.
If FreeCAD crashes or hangs on a job, only that one throwaway copy dies. cad_mcp reports an error to the AI, the model file on disk is untouched, and the AI can try something else.

5What the messages actually look like

MCP messages are small JSON texts, one per line. There are only a handful of message types. Click through the conversation:

// AI client → cad_mcp: "Hi, I speak MCP version 2025-06-18"
{"jsonrpc":"2.0","id":1,"method":"initialize",
 "params":{"protocolVersion":"2025-06-18","clientInfo":{"name":"claude-code"}}}

// cad_mcp → AI client: "Hi, I'm cad_mcp, I have tools, resources and prompts"
{"jsonrpc":"2.0","id":1,"result":{"serverInfo":{"name":"cad_mcp"},
 "capabilities":{"tools":{},"resources":{},"prompts":{}}}}
// AI client → cad_mcp: "what's on the menu?"
{"jsonrpc":"2.0","id":2,"method":"tools/list"}

// cad_mcp → AI client: 45 menu items (one shown)
{"jsonrpc":"2.0","id":2,"result":{"tools":[
  {"name":"add_primitive","description":"Add a primitive solid...","inputSchema":{...}},
  {"name":"run_fem","description":"Linear static stress analysis...","inputSchema":{...}},
  ... ]}}
// AI client → cad_mcp: "please call add_primitive with these inputs"
{"jsonrpc":"2.0","id":7,"method":"tools/call","params":{
  "name":"add_primitive",
  "arguments":{"doc":"bracket","name":"Plate","shape":"box",
               "dimensions":{"length":60,"width":40,"height":5},
               "material":"aluminium 6061"}}}
// cad_mcp → AI client: the result, as text the model can read
{"jsonrpc":"2.0","id":7,"result":{"content":[{"type":"text","text":
  "{ \"name\": \"Plate\", \"valid\": true, \"volume_mm3\": 12000.0,
     \"bbox\": [0,0,0, 60,40,5], \"material\": \"aluminium 6061\" }"}]}}

// The "id":7 matches the request, so the client knows which call this answers.
// Results can also be pictures. render_view returns a PNG the model can look at:
{"jsonrpc":"2.0","id":9,"result":{"content":[
  {"type":"text","text":"saved workspace/renders/bracket/iso.png"},
  {"type":"image","mimeType":"image/png","data":"iVBORw0KGgoAAAANSUhEUgAA..."}]}}

This is the whole protocol for tools. The repo's client_raw.py sends exactly these lines by hand, with no AI involved, so you can watch them scroll past.

6Inside the FreeCAD side

cad_mcp is split in two halves that never share memory. They only pass files to each other.

The job slip (what cad_mcp writes)

{ "op": "add_primitive",
  "doc": "workspace/bracket.FCStd",
  "args": {"name": "Plate", "shape": "box",
           "dimensions": {...}},
  "result": "/tmp/fcmcp_x/result.json" }

The FreeCAD code that runs (ops_model.py)

@op("add_primitive")
def add_primitive(doc, name, shape, dimensions, ...):
    if shape == "box":
        s = Part.makeBox(d["length"], d["width"],
                         d["height"])
    ...
    o = add_shape(doc, name, s, material)
    return describe(o)   # volume, bbox, ...
Why start a fresh FreeCAD for every job? It is simpler and safer. A long-running FreeCAD can crash, leak memory, or end up in a weird state. A fresh one per job always starts clean. The cost is about a second of start-up time per call.

7How the AI "sees" the part

Numbers alone can hide mistakes (a hole on the wrong face still has the right volume). So there is a render_view tool: FreeCAD exports the shape as triangles, cad_mcp draws them into a PNG, and the PNG goes back to the AI as an image. Modern models can look at images, so the AI checks its own work the way you would.

What the AI gets back from render_view(view="grid"): iso, front, top and side.
make_drawing runs FreeCAD's TechDraw to produce a real engineering drawing (SVG/PDF).

8Where the model lives (and how undo works)

📁 The file is the truth

The part is a normal FreeCAD file, workspace/bracket.FCStd. You can open it in the FreeCAD app at any time and see exactly what the AI built.

🕘 Undo = old copies

Before any change, cad_mcp copies the file into .history/bracket/0007.FCStd. undo just copies the previous one back. The last 20 versions are kept.

🧠 The AI remembers nothing

The AI doesn't hold the geometry in its head. It asks (list_objects, list_faces, render_view) whenever it needs to know the current state.

9What's on the menu

45 tools, plus two read-only resources (the list of documents, the material table) and one prompt (a ready-made "design and validate a bracket" recipe). Those are the three kinds of things an MCP server can offer.

📄 Documents

new_document, list_documents, list_objects, delete_object, set_properties, undo / history

🧱 Basic shapes

add_primitive (box, cylinder, sphere, cone, torus), extrude_polygon, boolean (cut, join, intersect), transform, fillet, chamfer

✏️ Sketch features

create_sketch, pad, pocket, revolve, loft, sweep, hole (incl. counterbore), shell, mirror, linear / polar pattern

🔍 Finding things

list_faces, list_edges, with selectors like normal:+Z z:max so the AI can say "the top face" instead of guessing a number

⚖️ Checks

mass_properties (mass, centre of mass, inertia), check_interference (do parts overlap?), clearance, section views

🧪 Stress analysis

run_fem: fix some faces, push on others, get max stress, max bend and the safety factor, plus a coloured stress picture

📐 Paperwork

make_drawing (TechDraw views + title block), bom (parts list as CSV / Markdown)

🔩 Assemblies

multiple parts, standard screws / nuts / washers by size, STEP parts library, exploded views

📤 Export & escape hatch

export (STEP, STL, 3MF, OBJ, DXF, FCStd), import_step, render_view, run_script for anything not on the menu

run_fem: 300 N on the bracket, max stress 50 MPa, safety factor 5.5 (aluminium 6061).
render_view(explode=1): the bracket with its standard bolts pulled apart.

10Explain it to anyone in 30 seconds

"An AI can only read and write text, so it can't use CAD software directly."

"So we wrote a small program, an MCP server, that sits next to FreeCAD. It hands the AI a menu: make a box, drill a hole, check the weight, test the strength, draw it. Each item says what inputs it needs."

"When the AI picks something, the server writes it on a slip, opens an invisible copy of FreeCAD, which does the real work on the actual CAD file, and passes the result back as text, or even as a picture the AI can look at."

"MCP is just the standard format for those slips, so the same server works with Claude, Codex, Cursor, anything."

Words worth knowing

MCP (Model Context Protocol)
The standard way AI apps talk to tool programs. Like USB, but for AI tools.
MCP client
The AI app (Claude Code, Codex, Claude Desktop). It starts the server and sends it requests.
MCP server
The tool program (cad_mcp). It offers tools, resources and prompts.
Tool
One menu item the AI can call, with typed inputs and a description.
JSON-RPC
The message format: small JSON texts with a method name, inputs, and an id to match answers to questions.
stdio
"Standard input/output": the two text pipes every program has. The client writes to the server's input and reads its output.
freecadcmd
FreeCAD without a window. Same engine, run from scripts.
FEM
Finite element method: splits the part into thousands of tiny pieces (Gmsh) and computes how it bends and where it is stressed (CalculiX).
